# КТЗ · Практикум

Учебное Windows-приложение для лабораторной №1: транспортная задача методом потенциалов, пошаговая проверка ответов, поддержка вырожденных планов.

## Запуск

Откройте `КТЗ-Практикум.exe` рядом с исходниками. Python и интернет для автономного EXE не нужны. Исходники запускаются командой `python app.py` (Python 3.10+ с Tkinter).

## Работа с задачей

1. Выберите встроенный вариант, загрузите JSON через «Загрузить вариант из файла» или создайте таблицу своей размерности.
2. Заполните тарифы, запасы и спрос. «Проверить баланс» проверяет данные без показа недостающего объёма и без предложения нужной стороны.
3. При необходимости самостоятельно выберите «Добавить строку» или «Добавить столбец» и заполните объём фиктивной вершины. Неверно выбранная сторона не исправляется автоматически. Для изменения выбора заново загрузите вариант или создайте таблицу.
4. Приступите к решению. Выбирайте клетки таблицы и вводите ответы на текущем этапе.
5. Потенциалы u вводятся в отдельный столбец справа, v — в отдельную строку снизу рабочей таблицы. После принятия они остаются в этих ячейках до перехода к следующему плану.
6. На этапе «Дальнейшее действие» студент выбирает «Продолжить» либо «Завершить». Автоматического сообщения «план оптимален» нет.

Масштаб таблиц регулируется вверху окна от 50 до 150 процентов. При изменении масштаба ввод потенциалов сохраняется, прокрутка доступна в обе стороны.

Подсказки, пояснения алгоритма и раскрывающие ответ сообщения убраны. Ошибочный ответ не меняет план и показывает только ошибку; правильный ответ переводит к следующему этапу. Считаются только ошибки. Журнал содержит принятые действия.

## Файлы вариантов

«Сохранить вариант в файл» сохраняет текущие исходные данные в JSON. Скопируйте `variants/variant-2.json`, чтобы подготовить новый вариант в текстовом редакторе:

- `costs` — прямоугольная матрица тарифов;
- `supply` — запасы по строкам;
- `demand` — спрос по столбцам;
- `dummy_row` / `dummy_col` — признак последней фиктивной строки / столбца, обычно оба `false`.

Принимаются неотрицательные целые до 10¹², от 1 до 30 реальных строк и столбцов, плюс одна фиктивная вершина. Несбалансированные исходные варианты можно сохранить и загрузить; перед решением требуется корректный баланс. Это файл условия задачи, текущий сеанс в нём не сохраняется.

## Математика

Базис хранится отдельно от перевозок: `0*` обозначает нулевую базисную клетку. Поддерживаются переходы θ=0 и правило Бланда против зацикливания. Внутреннее соглашение: vⱼ−uᵢ=cᵢⱼ, δ=v−u−c. Общий сдвиг потенциалов принимается.

Контрольные оптимумы: пример — 1370, варианты 1/4 — 830, вариант 2 — 1620, вариант 3 — 1240. В варианте 3 тариф 100 — штраф из условия, а не абсолютный запрет; последняя строка является фиктивной. Вариант 5 не включён из-за противоречивых исходных данных.

## Проверка и сборка

- `python -m unittest -v test_transport test_ui` — математические проверки, 400 случайных задач против независимого min-cost-flow, все учебные экраны, ручная балансировка, ввод потенциалов, масштабирование и файлы вариантов.
- `python app.py --smoke-test` — создание интерфейса и начало сеанса.
- `python build.py` — PyInstaller-сборка `dist/KTZ-Practicum.exe` с копией `КТЗ-Практикум.exe` в корне проекта. Нужны Pillow и PyInstaller; локальные зависимости поддерживаются в `.build-deps`.

Модули: `transport.py` — математика, `lesson.py` — учебный сценарий, `app.py` — интерфейс, `presets.py` — примеры, `variant_files.py` — JSON-варианты. `test_oracle.py` — независимый тестовый решатель.

Полная визуальная приёмка нового интерфейса и проверка на компьютере заказчика остаются отдельным этапом. Локальная сборка не обновляет опубликованный GitHub-релиз автоматически.
