# КТЗ · Практикум

Первая рабочая версия нового учебного приложения для лабораторной №1.

## Запуск

Скачайте `KTZ-Practicum.exe` из раздела Releases репозитория и откройте его. Это автономная сборка для Windows x64: Python и интернет для работы не нужны. В локальном рабочем проекте файл `КТЗ-Практикум.exe` находится в этой же папке `ktz-practicum`, рядом с исходниками.

В исходниках приложение запускается командой `python app.py` (Python3.10+ с Tkinter). Внешние runtime-пакеты для исходников не требуются. Сборка сделана на Python3.12/Windows11; другие версии Windows пока отдельно не проверены.

## Как работать

1. Загрузите пример или вариант1–4. Для своей задачи задайте размерность (1–30), нажмите «Создать таблицу», заполните тарифы, запасы и спрос. В интерфейсе принимаются целые неотрицательные числа до10¹².
2. Нажмите «Проверить баланс». При несовпадении сумм добавьте фиктивную строку или столбец предложенной кнопкой, заполните объём и проверьте тарифы. Затем нажмите «Приступить к решению»: ошибки баланса или тарифов блокируют переход к шагу 2. Автоматического исправления при запуске решения нет.
3. В рабочей таблице выбирайте клетку минимального тарифа, затем вводите максимально возможный объем перевозки. При равных минимальных тарифах допускается любой выбор.
4. Изучите начальный базис. `0*` означает базисную клетку с точным нулевым объемом, `·` — пустую небазисную клетку. Нулевые клетки дополняются автоматически без образования цикла.
5. Введите потенциалы строк u и столбцов v через пробел. Используется соглашение старой лабораторной: **vⱼ−uᵢ=cᵢⱼ** для базисных клеток. Допустимы отрицательные числа и любой согласованный общий сдвиг. Пустые клетки не задают равенств; клетки0* задают.
6. Оцените оптимальность по δ=v−u−c. Если есть положительные оценки, выберите входящую клетку; правило выбора написано в задании справа.
7. Отметьте остальные клетки цикла, введите θ и подтвердите переход к новому плану. Повторяйте до оптимума.

Слева в таблице показан тариф c, крупно — перевозка; после проверки потенциалов внизу появляется оценкаδ. На этапах цикла знаки+ и− имеют разные цвета. Остатки запасов/спроса при построении НОП показаны справа/снизу.

Вкладки содержат исходную (сбалансированную) матрицу и журнал правильных шагов. После проверки принятые потенциалы отображаются серым цветом в заголовках строк и столбцов рабочей таблицы; формула оценок указана под таблицей. После перехода к новому плану потенциалы скрываются до проверки новых значений. Ошибки и использованные подсказки считаются отдельно. Неправильный ответ сохраняет текущую задачу и введенные поля. «Новая задача» во время решения требует подтверждения завершения сеанса. Данные сеанса хранятся в памяти до закрытия приложения, сохранение в файл пока не реализовано.

## Вырожденный план

Базис хранится отдельно от матрицы объемов, как остов двудольного графа из m+n−1 клеток. Нулевые перевозки не заменяются маленькими положительными числами. Потенциалы и цикл учитывают нулевые базисные клетки.

При θ=0 перевозки не меняются, но базис меняется. На вырожденном плане включается правило Бланда: первая по номеру строки/столбца небазисная клетка с δ>0; выходящая клетка — первая из минусовых с минимальным объемом. После включения это правило сохраняется для следующих итераций. Это осознанное отличие от безусловного максимумаδ в старом тренажере, необходимое для надежной защиты от циклов. Дополнительно контролируются повтор базиса и лимит10000 итераций.

Для знакомства есть пресеты «Вырожденный план» и «Нулевые запасы». Последний используется также при проверке экранов с нулевыми базисными клетками.

## Учебные данные

Оптимум контрольного примера **1370**, вариантов1/4 —830,2 —1620,3 —1240. Старые значения1410/1490 из документации не копируются. Вариант5 не включен: его исходная размерность противоречива.

В варианте3 последняя строка уже является фиктивным поставщиком на30. Стоимость100 на направлениях1 и4 — штраф, как в методичке; он не является абсолютным запретом. Приложение явно сообщает об этом при загрузке. Пользовательские абсолютные запреты маршрутов в эту версию не добавлялись.

## Проверки и сборка

- `python -m unittest -v test_transport test_ui` —10 тестов, включая сравнение400 задач с независимым min-cost-flow, контрольные оптимумы, полный учебный сеанс, ошибочные ответы, сдвиг потенциалов, большие тарифы и целые числа, нулевые суммы, переход θ=0 и отрисовку всех10 состояний UI.
- `python app.py --smoke-test` — проверка создания Tk-интерфейса, редактора, балансировки и первой учебной страницы с закрытием окна.
- `python build.py` — упаковка PyInstaller в один Windows EXE; для пересборки нужны Pillow и PyInstaller (в этом проекте PyInstaller установлен локально в `.build-deps`).

Модули: `transport.py` — точная целочисленная математика; `lesson.py` — учебный сценарий; `app.py` — интерфейс; `presets.py` — примеры. Тестовый независимый решатель — `test_oracle.py`; тесты не требуют файлов за пределами репозитория. Материалы исследования старой программы в этот репозиторий не включены.

Для пересборки в чистом окружении установите инструменты: `python -m pip install pillow pyinstaller`. Затем выполните `python build.py`. Скрипт создаст `dist/KTZ-Practicum.exe` и копию `КТЗ-Практикум.exe` в корне этого репозитория. Все результаты сборки остаются внутри `ktz-practicum`.

Эта версия готова для первого просмотра и проверки заказчиком. Полная приемка на компьютере заказчика, проверка всех масштабов экрана и всех ручных сценариев еще не выполнены. Наблюдение GUI через Computer Use в текущем окружении возвращало изображение перекрывающего окна вместо содержимого Tk; автоматическая проверка создания всех экранов выполнена, полноценная визуальная приемка остается отдельным шагом.
